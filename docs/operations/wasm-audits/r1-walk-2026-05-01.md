# r1 WASM walk — comprehensive history

> WASM hash timeline for every Soroban source we ingest, from r1's full
> Galexie archive walk (`s3://galexie-archive`, ledgers 50,457,424 →
> 62,296,694) captured 2026-04-30, plus Soroban-RPC current-state queries for
> never-upgraded contracts the walker missed.
>
> **Coverage: 540 / 543 contracts attributed across 8 sources (99.4 %)**,
> including all 11 Blend contracts. All 52 unique WASMs fetched +
> SHA-256-verified + disassembled + classified by exported function signatures.

## What this answers

Per protocol/oracle producing canonical trades:

1. **Which contracts are deployed on mainnet** — every factory, router,
   per-instance pool, oracle.
2. **When deployed** — first-seen ledger from the walk, or "pre-walk-window"
   for never-upgraded WASMs.
3. **When upgraded** — every `update_current_contract_wasm` event as a
   contiguous ledger range per WASM hash.
4. **Result of an upgrade** — factory upgrades cascade onto pools deployed
   afterwards; existing instances stay on their old WASM until upgraded.
5. **What each WASM does** — exports + symbol strings from disassembly,
   classified into roles (`<source>-{factory,router,pool,multihop,oracle,...}`).

## Tooling gaps surfaced

1. **`stellarindex-ops extract-wasm-from-galexie` returns MISSING for every hash.**
   Tested 2026-05-01 on several subsets of the 50 hashes and a 12M-ledger
   archive range: zero matches. Workaround: fetch WASM bytes via Soroban-RPC
   `getLedgerEntries` against the ContractCode LedgerKey; all 50 resolved and
   SHA-256 matches the walker's hash 50/50. The tool has a real bug (the
   wasm-history walker reads the same archive cleanly); likely a
   `LedgerEntryChange`-discriminator mismatch or the `Created` change arriving
   under a different metadata variant. **Fix as a separate code change.**

2. **wasm-history walker only emits transitions, not initial state.** Caused the
   283 false negatives (`ranges: null`) and the earlier wrong Aquarius
   "doc rot" conclusion. It should emit the *current* hash for any watched
   contract with no transitions in range. Tracked.

3. **Three contracts labelled Aquarius router, Phoenix multihop anchor and
   Aquarius admin anchor returned `not_found` from the RPC current-state query.**
   All three are Reflector testnet oracles absent on mainnet, not TTL-evicted
   mainnet anchors ([walker-investigation-2026-05-01.md §2](walker-investigation-2026-05-01.md)).
   No residual: the real Aquarius router (`CBQDHNBF…`) and Phoenix multihop
   (`CCLZRD4E…`) are walked.

4. **The 532-contract input list isn't curated in repo.** Curate
   `configs/audit/wasm-walk-contracts.yaml` per source with provenance.
