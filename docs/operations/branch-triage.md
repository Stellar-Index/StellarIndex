# Branch triage

How to decide whether a branch still carries work `main` lacks, and what deleting it
costs. Method in §1–§3; §4–§5 are what the 2026-09-09 pass left.

## 1. Why eyeballing fails

- Work lands by `gh pr merge --squash` or rebase, which re-authors commits: a landed
  branch's tip is not an ancestor of `main`, no patch id matches, and every file reads as
  changed.
- Branches sit hundreds of commits behind. `git diff --stat main...branch` is the
  merge-base diff and hides what `main` gained since the fork; the two-dot diff is the real
  effect. `scripts/dev/branch-status.sh` exists for this.
- Ancestry alone under-reports landing by ~10×.

## 2. The four tests, strongest first

Stop at the first that fires. All exact except test 4.

| # | Test | Command | Proves |
|---|---|---|---|
| 1 | **Ancestry** | `git merge-base --is-ancestor <b> main` | Tip is in `main`; `git branch -d` accepts it. |
| 2 | **Tree identity** | `git rev-parse <b>^{tree}` appears in `git log --format=%T main` | A squash landed the whole tree. |
| 3 | **Patch id** | `git cherry main <b>` shows no `+` | Every commit has an equivalent; survives rebase/cherry-pick. |
| 4 | **Content presence** | every line the branch ADDED appears in `main`'s tree | Heuristic, not proof. |

`make branch-status` runs tests 1 and 3; 2 and 4 are manual (§3).

None of them catches a **squash of several commits** (one new patch id, tree is `main`'s),
the usual landing route. Settle those with test 4 plus a by-hand trace.

Test 4 trap: a landed line that `main` later edited is not found, so a ratio below 1.0 is
not "unlanded". **≥ 0.95**: residue is CHANGELOG, doc wording and test-helper drift.
**< 0.95**: hand-verify. Exclude `examples/postman/stellar-index.postman_collection.json`
(regenerated by `scripts/dev/docs-postman.sh`) and `CHANGELOG.md` first.

A stronger test for "is this the only copy": **blob presence**, does every file the branch
changes exist in `main`'s history at the same path. Landed branches report 0 absent.

## 3. Running a pass

```sh
# 1. Ancestry + patch id; exits 3 if any branch would delete files main has.
make branch-status
BRANCH_STATUS_ARGS='--stale-only' make branch-status   # hide what has landed

# 2. Tree identity (test 2), every branch at once.
git log --format='%T %h %s' main > /tmp/main-trees
git for-each-ref --format='%(refname:short)' refs/heads/ | grep -v '^worktree-' |
  while read -r b; do
    t=$(git rev-parse "$b^{tree}")
    hit=$(grep -m1 "^$t " /tmp/main-trees) && echo "$b  LANDED WHOLE as ${hit#* }"
  done

# 3. Find the squash that carried an unresolved branch.
git log --oneline main --grep='<issue number>'
git log --oneline main --grep='<a distinctive phrase from the branch subject>'
git log -S '<a symbol or string the branch introduced>' main -- <path>

# 4. Prove the branch adds nothing main lacks. EMPTY is the strongest answer:
git diff --stat <branch> <the-main-commit-you-found>
```

Branches settled by tests 2–4 need `git branch -D` (`-d` checks ancestry); record the
evidence before deleting. Ignore `worktree-*` refs (agent scratch from
`scripts/dev/bootstrap-worktree.sh`; `branch-status.sh` filters them).

Never `git merge` a branch this far behind: it would delete files `main` has. To apply one,
rebase it or cherry-pick commits after reading `git show --name-status <sha>`.

## 6. Keeping the pile small

`.github/workflows/orphan-branches.yml` runs daily over **remote** branches with no
open-or-merged PR and a last commit over 24 h old, and maintains one tracking issue. It
does not see local branches. The contract is
[CONTRIBUTING.md — No orphan work](../../CONTRIBUTING.md#no-orphan-work--the-contract);
deleting the branch is the last step of merging it.
